# B33 + B34 Backend Hygiene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop psycopg_pool from echoing a malformed `FW_DATABASE_URL` into logs (B33, #110) and make the test suite's sqlite connection hygiene deterministic and gate-enforced (B34, #112).

**Architecture:** B33 adds a parse pre-check in `PostgresDatabase.__init__` so malformed DSNs are rejected with a variable-name-only error before psycopg_pool ever sees the string. B34 pins ResourceWarning (and its GC-time unraisable wrapper) to error in the pytest config FIRST, observes the red state, then converts leaky `with sqlite3.connect(...)` test sites to `contextlib.closing`, with one narrowly scoped ignore for spylls' upstream file-handle leak.

**Tech Stack:** Python 3.13, psycopg 3 (`psycopg.conninfo.conninfo_to_dict`), pytest (`filterwarnings` ini option), sqlite3.

**Spec:** `docs/superpowers/specs/2026-08-18-b33-b34-backend-hygiene-design.md`

## Global Constraints

- Working directory for all commands: `backend/` (run via `rtk proxy uv run …`).
- Gates: `rtk proxy uv run pytest -q` must be green with ZERO warnings, both WITHOUT `FW_TEST_DATABASE_URL` (PG tests skip; no Docker/network) and WITH it set to the local stack DSN if available.
- **ResourceWarning verification of a single file or subset MUST use `-n0` — under `-n auto` xdist workers swallow the GC-time unraisable error and a real leak runs green (probed: 3× green on then-leaky `test_usage.py`).** The FULL suite under `-n auto` does surface the findings.
- **Judge mutation-verify runs by EXIT CODE, never by grepping the summary:** the GC-time error can surface AFTER the `N passed` line as a post-session traceback (exit 1). Legitimate failure shapes: (a) a test/teardown ERROR, (b) `N passed` + post-session traceback + exit 1, (c) an `ExceptionGroup` of multiple unraisable warnings.
- `PYTHONTRACEMALLOC=15` is an ON-DEMAND diagnostic, not a blanket requirement (it multiplies suite runtime): run gates WITHOUT it; add it only when re-running a single file (`-n0`) to attribute a NEW, unexpected finding — GC timing otherwise attributes findings to innocent tests (probed: a `test_usage.py` leak reported against a *skipped* test). The known finding set is already attributed (two sqlite sites + spylls).
- Error messages may name the VARIABLE `FW_DATABASE_URL`, NEVER its value. No secret values in code, tests, logs, or commits.
- Never read or write `backend/data/fabulous.db`; all tests use `tmp_path`.
- Never touch ports 5173/8000 or the running supabase stack.
- Mutation-verify every guard test: break the guarded code by re-editing, watch the test fail, restore by re-editing — NEVER `git checkout <file>`.
- Every commit message ends with the two standing trailers (Co-Authored-By + Claude-Session).
- Branch: `b33-b34-hygiene`. PR closes #110 and #112 via separate `Closes` lines (handled at PR time, not in this plan).

```python
class TestPostgresDsnPrevalidation:
    """B33 (#110): a malformed DSN must be rejected by the app before
    psycopg_pool sees it — the pool's own logger echoes the raw value
    (password included, if the operator mangled a real DSN)."""

    MALFORMED = "not-a-dsn-s3cret-fragment"

    def test_malformed_dsn_raises_naming_only_the_variable(
        self, caplog, monkeypatch
    ):
        from app.services.db import postgres

        class PoolMustNotBeConstructed:
            def __init__(self, conninfo, **kwargs):
                raise AssertionError("pool must never see a malformed DSN")

        # The invariant is "the raw value never reaches psycopg_pool",
        # not merely "no log line appeared": a stub pool that explodes on
        # construction asserts it directly.
        monkeypatch.setattr(postgres, "ConnectionPool", PoolMustNotBeConstructed)
        with caplog.at_level(logging.DEBUG):
            with pytest.raises(RuntimeError) as excinfo:
                postgres.PostgresDatabase(self.MALFORMED)
        message = str(excinfo.value)
        assert "FW_DATABASE_URL" in message
        assert self.MALFORMED not in message
        # `raise ... from None`: psycopg's parse error embeds the raw
        # string, so no traceback layer may carry it.
        assert excinfo.value.__cause__ is None
        assert excinfo.value.__suppress_context__ is True
        assert self.MALFORMED not in caplog.text

    @pytest.mark.parametrize(
        "dsn",
        [
            "postgresql://user:secret@localhost:5432/db",
            "host=localhost dbname=db user=u password=p",
        ],
        ids=["url-form", "keyvalue-form"],
    )
    def test_valid_dsn_forms_reach_pool_construction(self, dsn, monkeypatch):
        # Guards against OVER-strict validation: everything libpq accepts
        # — both DSN forms — must reach ConnectionPool unchanged
        # (stubbed; no server involved).
        from app.services.db import postgres

        seen = {}

        class StubPool:
            def __init__(self, conninfo, **kwargs):
                seen["conninfo"] = conninfo

            def wait(self, timeout=None):
                pass

        monkeypatch.setattr(postgres, "ConnectionPool", StubPool)
        postgres.PostgresDatabase(dsn)
        assert seen["conninfo"] == dsn
```

Note: parse-only tests — no server, no `FW_TEST_DATABASE_URL`, they run in the default gate. They import psycopg (a regular dependency), consistent with `TestCreateDatabase`'s existing style.

- [ ] **Step 1: Pin the gate (with the spylls ignore) in pyproject**

In `backend/pyproject.toml`, `[tool.pytest.ini_options]`, add:

```toml
filterwarnings = [
    # B34 (#112): unclosed sqlite connections must fail the suite, not
    # scroll past as ignored-by-default ResourceWarnings. The second
    # entry catches the GC-time case: a ResourceWarning raised inside
    # __del__ cannot propagate and reaches pytest via the unraisable-
    # exception hook as PytestUnraisableExceptionWarning instead.
    "error::ResourceWarning",
    "error::pytest.PytestUnraisableExceptionWarning",
    # spylls never closes its dictionary file handles (upstream:
    # spylls/hunspell/readers/file_reader.py, reached via
    # app/checkers/llm/vetting.py Dictionary.from_files; the _hunspell
    # cache bounds the leak to one handle set per language per process).
    # Scoped to unclosed-FILE warnings from the dictionaries path only —
    # unclosed sqlite CONNECTIONS still fail (Step 6 proves it). Later
    # entries take precedence in pytest, so these sit below the errors.
    "ignore:(?s).*unclosed file.*dictionaries.*:pytest.PytestUnraisableExceptionWarning",
    "ignore:(?s).*unclosed file.*dictionaries.*:ResourceWarning",
]
```

If the red run in Step 2 shows the spylls findings NOT matching these patterns (the wrapper's message layout is pytest-version-dependent), adjust the regex minimally until the spylls findings are ignored — it must keep matching `unclosed file` + the dictionaries path, and must NOT mention sqlite or widen beyond files. def _read_usage_rows(db_path: Path) -> list[sqlite3.Row]:
    with sqlite3.connect(db_path) as conn:
        conn.row_factory = sqlite3.Row

```python
def _read_usage_rows(db_path: Path) -> list[sqlite3.Row]:
    # `with sqlite3.connect(...)` alone only manages the transaction; the
    # connection itself must be closed deterministically (#112).
    with closing(sqlite3.connect(db_path)) as conn:
        conn.row_factory = sqlite3.Row
        return conn.execute("SELECT * FROM llm_usage ORDER BY id").fetchall()
```
