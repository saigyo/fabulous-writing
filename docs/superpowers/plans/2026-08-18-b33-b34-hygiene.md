# B33 + B34 Backend Hygiene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop psycopg_pool from echoing a malformed `FW_DATABASE_URL` into logs (B33, #110) and make the test suite's sqlite connection hygiene deterministic and gate-enforced (B34, #112).

**Architecture:** B33 adds a parse pre-check in `PostgresDatabase.__init__` so malformed DSNs are rejected with a variable-name-only error before psycopg_pool ever sees the string. B34 converts leaky `with sqlite3.connect(...)` test sites to `contextlib.closing`, then pins ResourceWarning (and its GC-time unraisable wrapper) to error in the pytest config.

**Tech Stack:** Python 3.13, psycopg 3 (`psycopg.conninfo.conninfo_to_dict`), pytest (`filterwarnings` ini option), sqlite3.

**Spec:** `docs/superpowers/specs/2026-08-18-b33-b34-backend-hygiene-design.md`

## Global Constraints

- Working directory for all commands: `backend/` (run via `rtk proxy uv run …`).
- Gates: `rtk proxy uv run pytest -q` must be green with ZERO warnings, both WITHOUT `FW_TEST_DATABASE_URL` (PG tests skip; no Docker/network) and WITH it set to the local stack DSN if available.
- Single-file pytest runs use `-n0` (the suite default is `-n auto`).
- Error messages may name the VARIABLE `FW_DATABASE_URL`, NEVER its value. No secret values in code, tests, logs, or commits.
- Never read or write `backend/data/fabulous.db`; all tests use `tmp_path`.
- Never touch ports 5173/8000 or the running supabase stack.
- Mutation-verify every guard test: break the guarded code by re-editing, watch the test fail, restore by re-editing — NEVER `git checkout <file>`.
- Every commit message ends with the two standing trailers (Co-Authored-By + Claude-Session).
- Branch: `b33-b34-hygiene`. PR closes #110 and #112 via separate `Closes` lines (handled at PR time, not in this plan).

Add to `backend/tests/test_db_seam.py`, directly after the `TestCreateDatabase` class (module already imports `logging` and `pytest`):

```python
class TestPostgresDsnPrevalidation:
    """B33 (#110): a malformed DSN must be rejected by the app before
    psycopg_pool sees it — the pool's own logger would echo the raw
    value (password included, if the operator mangled a real DSN)."""

    MALFORMED = "not-a-dsn-s3cret-fragment"

    def test_malformed_dsn_raises_naming_only_the_variable(self, caplog):
        from app.services.db.postgres import PostgresDatabase

        with caplog.at_level(logging.DEBUG):
            with pytest.raises(RuntimeError) as excinfo:
                PostgresDatabase(self.MALFORMED)
        message = str(excinfo.value)
        assert "FW_DATABASE_URL" in message
        assert self.MALFORMED not in message
        # `raise ... from None`: psycopg's parse error embeds the raw
        # string, so no traceback layer may carry it.
        assert excinfo.value.__cause__ is None
        assert excinfo.value.__suppress_context__ is True
        assert self.MALFORMED not in caplog.text

    @pytest.mark.parametrize(
        "dsn",
        [
            "postgresql://user:secret@localhost:5432/db",
            "host=localhost dbname=db user=u password=p",
        ],
        ids=["url-form", "keyvalue-form"],
    )
    def test_valid_dsn_forms_reach_pool_construction(self, dsn, monkeypatch):
        # Pre-validation must accept everything libpq accepts: both DSN
        # forms reach ConnectionPool unchanged (stubbed — no server).
        from app.services.db import postgres

        seen = {}

        class StubPool:
            def __init__(self, conninfo, **kwargs):
                seen["conninfo"] = conninfo

            def wait(self, timeout=None):
                pass

        monkeypatch.setattr(postgres, "ConnectionPool", StubPool)
        postgres.PostgresDatabase(dsn)
        assert seen["conninfo"] == dsn
```

Note: these are parse-only tests — no server, no `FW_TEST_DATABASE_URL`, they run in the default gate. They import psycopg (installed as a regular dependency), consistent with `TestCreateDatabase`'s existing style.

- [ ] **Step 1: Fix the two confirmed leaky sites**

`backend/tests/test_usage.py` — add `from contextlib import closing` to the imports, then at ~line 258 replace:

```python
    with sqlite3.connect(settings.db_path) as conn:
        (status,) = conn.execute(
            "SELECT status FROM llm_usage WHERE run_id = 'orphan'"
        ).fetchone()
```

with:

```python
    with closing(sqlite3.connect(settings.db_path)) as conn:
        (status,) = conn.execute(
            "SELECT status FROM llm_usage WHERE run_id = 'orphan'"
        ).fetchone()
```

`backend/tests/test_check_api.py` — add `from contextlib import closing` to the imports, then replace `_read_usage_rows` (~line 855):

```python
def _read_usage_rows(db_path: Path) -> list[sqlite3.Row]:
    with sqlite3.connect(db_path) as conn:
        conn.row_factory = sqlite3.Row
        return conn.execute("SELECT * FROM llm_usage ORDER BY id").fetchall()
```

with:

```python
def _read_usage_rows(db_path: Path) -> list[sqlite3.Row]:
    # `with sqlite3.connect(...)` alone only manages the transaction; the
    # connection itself must be closed deterministically (#112).
    with closing(sqlite3.connect(db_path)) as conn:
        conn.row_factory = sqlite3.Row
        return conn.execute("SELECT * FROM llm_usage ORDER BY id").fetchall()
```

Both sites are read-only, so dropping the transaction-scope `with conn` behavior is semantically a no-op (SELECTs need no commit; the implicit rollback on close is empty).
