# B35 About Dialog and Instance Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make it obvious which instance of Fabulous Writing the browser is pointed at: an About dialog (version, database, GitHub link, copyright) plus an always-visible `dev · <backend>` badge under the wordmark on dev builds.

**Architecture:** Backend adds one field (`db_backend`) to the authenticated `/auth/me` response; `/api/health` stays byte-identical. Frontend stores the already-fetched health `version`, reads `db_backend` off the existing `user` object, and composes the About surface from the existing `AccountMenu` + `Dialog` primitives; the badge is a second line inside a new `brand` flex-column in the header.

**Tech Stack:** FastAPI/Pydantic (backend), React 19 + zustand store + vitest (frontend), 7-locale message catalogs.

**Spec:** `docs/superpowers/specs/2026-08-18-b35-about-dialog-design.md`

## Global Constraints

- Backend commands from `backend/` via `rtk proxy uv run pytest …`; single-file runs `-n0`; full gate green ZERO warnings (~1509 passed / 166 skipped without `FW_TEST_DATABASE_URL`).
- Frontend gates from `frontend/`: `npm run test` (vitest run — transpile-only, does NOT typecheck), `npm run lint` (oxlint), AND `npm run build` (`tsc -b` — this is where type errors surface, and CI requires it). All three clean at every frontend commit.
- This repo has NO `@testing-library/jest-dom`: matchers like `toBeInTheDocument`/`toHaveAttribute` do not exist. Use the house idioms — `screen.getByText(x)` (throws when absent), `expect(screen.queryByText(x)).toBeNull()`, `expect(el.getAttribute('href')).toBe(...)` — and do NOT add the dependency.
- `/api/health` must stay byte-identical; the existing full-dict equality assertion in `backend/tests/test_health.py:16-31` IS the shape guard — it must keep passing unchanged, and no duplicate guard is added.
- The header must not grow: it has `min-height: 68px` (the App.css comment's "fixed height" is intent, not a cap); the wordmark+badge column (~32px at line-height 1.1) stays well below it. The `max-width: 1080px` media query hides the wordmark (`.header h1 { display: none }`) — the badge must hide with it.
- New locale strings in ALL 7 catalogs (en de fr es it ja zh); the literals `dev`, `—`, `SQLite`, `PostgreSQL`, `GitHub`, and `© 2026 Markus Ackermann` are deliberately NOT localized. The new strings contain no direct user address, so the informal-register rule is satisfied vacuously — do not force one in.
- The GitHub link href is the hardcoded literal `https://github.com/saigyo/fabulous-writing` with `target="_blank" rel="noopener noreferrer"`. No dynamic hrefs.
- Mutation-verify every guard test by re-editing (never `git checkout`).
- Never read/write `backend/data/`; never touch ports 5173/8000 or supabase containers.
- Every commit ends with the two standing trailers (Co-Authored-By + Claude-Session).
- Branch `b35-about`; PR closes #113. The LOGBOOK entry happens on the owner's cue at PR time — not part of these tasks.
